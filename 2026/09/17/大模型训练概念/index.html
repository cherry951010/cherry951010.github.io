大模型训练流程概念

训练主流程

相关概念

  1. 预训练

    • 最烧钱、最核心

    • 产出Base Model

    • 目的：能续写文本

  2. 后训练第一步：SFT

    • 模型会不会听指令

    • 回答风格是否稳定

    • 某些任务格式是否固定

    • 某个领域的表达方式是否更贴合

    • 工具调用、JSON 输出、分类抽取是否更规范

  3. RLHF\DPO

    • 让模型更倾向于输出人类更喜欢的答案
    • RLHF:让模型对一个问题回答多个答案，人工标注哪个合适，再训练奖励模型，学习人类偏好，用强化学习，让模型往奖励方向调整
    • DPO：直接一些，可以用“好回答 / 坏回答”成对数据来优化模型，不一定要单独训练奖励模型；是让模型突然懂了新知识，而是让模型更像一个靠谱助手

  4. 推理

    • 首个token是根据用的Prompt来的，后续根据前面的token继续推理

  5. 上下文窗口

    • 系统提示词
    • 历史对话
    • 当前用户问题
    • 工具返回结果
    • RAG 检索出来的资料

  6. KV Cache

    • 推理加速的关键

  7. Temperature

    • temperature 越低，模型越保守。

      适合代码、分类、结构化输出、严肃问答。

      temperature 越高，模型越发散。

      适合创意写作、头脑风暴、广告文案。

  8. Top-p

    • 限制采样范围
    • 只在累计概率达到 90% 的候选 token 里挑

  9. 大模型幻觉

    • 本身擅长语言类组织
    • 它可能不知道自己不知道

阶段

训练阶段：把海量文本里的规律压进参数；

推理阶段：根据当前 prompt 一个 token 一个 token 往外生成。

  • 预训练：学语言、知识和“问题后面接解释”的通用模式
  • SFT：学“用户提问后，助手应该认真回答”的指令格式
  • RLHF / DPO：学什么样的回答更受人类喜欢
  • 推理：把当前用户问题作为上下文，按已经学到的模式生成答案

这几个步骤不是互相替代，而是接力关系。

  • 没有预训练，模型没有基础能力。

  • 没有 SFT，模型可能会续写，但不一定像助手。

  • 没有对齐，模型可能能回答，但不一定好用。

  • 没有推理，训练好的能力也不会变成当前这次对话里的具体答案。

总结

  1. 为什么要预训练？

    • 因为模型一开始什么都不会，参数就是一堆没调好的数字。

  2. 为什么要 SFT？（监督微调）

    • 因为 Base Model 只会续写，不一定知道自己要当助手。

  3. 为什么要 RLHF、DPO？（强化学习，直接偏好优化）

  • 因为会回答不代表答得好，模型还得学人类喜欢什么样的答案。

  1. 为什么会幻觉？

    • 因为它本质上是在生成最可能的 token，不是在查数据库。

  2. 为什么 RAG、工具调用、评测这么重要？

    • 因为真实业务不能靠“看起来像对的”上线。

做大模型应用开发，不一定要亲手训练一个千亿参数模型。但你必须知道模型是怎么来的。

不然很容易犯两个低级错误：

  • 一个是把模型当神，觉得什么问题都能问它。

  • 另一个是把模型当普通接口，觉得调一下参数就能稳定解决业务问题。

大模型应用开发真正难的地方，不是把 API 调通。

而是你要知道：

什么该交给模型，什么该交给检索，什么该交给工具，什么必须做校验。
